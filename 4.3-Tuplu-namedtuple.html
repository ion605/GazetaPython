Tupluri cu câmpuri denumite - Tuples With Named Fields

În Python, tuplurile cu câmpuri denumite se creează folosind collections.namedtuple sau typing.NamedTuple, care permit accesarea elementelor prin atribute descriptive, în loc de indici numerici.

In Python, tuples with named fields are created using collections.namedtuple or typing.NamedTuple, which allow elements to be accessed via descriptive attributes instead of numeric indices.

namedtuple este o funcție-fabrică disponibilă în modulul collections, care creează subclase de tupluri cu câmpuri denumite. O fabrică este un obiect destinat creării altor obiecte. Este o funcție sau o metodă care returnează obiecte.

Un nume de câmp este un identificator de tip șir de caractere utilizat pentru a accesa un anumit element după nume, în loc de un indice numeric (fruct.culoare în loc de fruct[1]).

Un namedtuple moștenește toate caracteristicile unui tuplu obișnuit — este imuabil, eficient din punctul de vedere al memoriei, iterabil și permite despachetarea — făcând în același timp codul mult mai curat și auto-documentat.

namedtuple is a factory function available in the collections module that creates tuple subclasses with named fields. Factory is an object for creating other objects. It is a function or method that returns objects.

A field name is a string identifier used to access a specific element by name instead of a numeric index (fruct.color instead of fruct[1]).

A namedtuple inherits all regular tuple features—it is immutable, memory-efficient, iterable, and unpackable—while making your code significantly cleaner and self-documenting

Pentru a ilustra modul în care funcționează câmpurile cu nume, să presupunem că dorești să stochezi datele unei persoane într-o secvență imuabilă — precum un tuplu.

Persoană = namedtuple("Persoană", "nume vârstă educație")

În Persoană = namedtuple("Persoană", "nume vârstă educație"), primul Persoană este numele clasei (noul tip de date), iar al doilea Persoană este numele intern al tipului, utilizat de Python pentru afișare și depistare a erorilor.

Practică bună
Păstrează ambele nume identice. Modificarea celui de-al doilea șir (de exemplu, în namedtuple("ID", ...)) în timp ce păstrezi variabila Persoană îi va induce în eroare pe cei care îți citesc codul.

To illustrate how the named fields works, say that you want to store a person data in an immutable sequence—like a tuple.

Person = namedtuple("Person", "name age education")

In Person = namedtuple("Person", "name age education"), the first Person is the class name (the new data type), and the second Person is the internal type name used by Python for printing and debugging.

Best Practice
Keep both names identical.Changing the second string to something else (like namedtuple("ID", ...) while keeping the variable Person) confuses anyone reading your code.

Nu se recomandă utilizarea unui set pentru a specifica numele câmpurilor într-un namedtuple din Python.

It is not recommended to use set to provide the field names in python namedtuple.

De ce nu ar trebui folosite seturile
În cazul tipului set, ordinea elementelor se pierde, iar dispunerea acestora devine imprevizibilă și se modifică aleatoriu, în funcție de valoarea inițială de seed pentru hashing a interpretorului Python.
Deoarece ordinea câmpurilor este imprevizibilă, instanţierea tuplului folosind argumente poziţionale (de exemplu, presoană("Valdi", 63)) va atribui în mod arbitrar valori unor câmpuri greşite.
Dacă utilizezi parametrul pentru valori implicite, Python asociază aceste valori câmpurilor din extremitatea dreaptă. O ordine imprevizibilă a setului face imposibilă alinierea sigură a valorilor implicite cu câmpurile cărora le sunt destinate.
Why Sets Should Not Be Used
In the case of the set type, the order of elements is lost, and their arrangement becomes unpredictable and changes randomly, depending on the Python interpreter's initial hashing seed value.
Since the order of the fields is unpredictable, instantiating the tuple using positional arguments (e.g., persoană("Valdi", 63)) will arbitrarily assign values ​​to the wrong fields.
If you use the defaults parameter, Python maps those defaults to the rightmost fields. An unpredictable set order makes it impossible to safely align default values with their intended fields.

Metode și atribute încorporate - Built-in Methods and Attributes

namedtuple din Python oferă câteva metode și atribute speciale, care au ca prefix un caracter de subliniere pentru a evita conflictele cu numele câmpurilor definite de utilizator.

Python's namedtuple provides several special methods and attributes that are prefixed with an underscore to avoid name conflicts with user-defined field names.

  • _make(iterable): Creează o nouă instanță a tuplului pornind de la orice secvență sau colecție iterabilă.
  • _asdict(): Convertește instanța tuplului cu nume într-un dicționar (mai exact, un OrderedDict în versiunile mai vechi sau un dicționar conform standardului).
  • _replace(**kwargs): Returnează o nouă instanță a tuplului cu nume, având câmpurile specificate actualizate, respectând totodată natura imuabilă a tuplurilor.
  • _fields: Un tuplu de caractere care listează toate numele câmpurilor în ordinea definirii lor; util pentru introspecție.
  • _field_defaults: Un dicționar care asociază numele câmpurilor ce au valori implicite cu valorile implicite respective.
  • _make(iterable): Creates a new instance of the named tuple from any iterable sequence or collection.
  • _asdict(): Converts the named tuple instance into a dictionary (specifically an OrderedDict in older versions or standard-compatible dict behavior).
  • _replace(**kwargs): Returns a new instance of the named tuple with specified fields updated, respecting the underlying immutability of tuples.
  • _fields: A tuple of strings listing all the field names in the order they were defined, useful for introspection.
  • _field_defaults: A dictionary mapping field names that have default values to their respective default values.
from collections import namedtuple

# Definește un namedtuple cu o valoare implicită
Punct = namedtuple("Punct", ["x", "y", "z"], defaults=[14])

# _fields and _field_defaults
print(f"Parametrii originali: {Punct._fields} / type({Punct._fields})")
==> Parametrii originali: ('x', 'y', 'z') / <class 'tuple'>

print(f"Valoare implicită: {Punct._field_defaults} / type({Punct._field_defaults})")
==> Valoare implicită: {'z': 14} / <class 'dict'>

# _make()
punct1 = Punct._make([10, 20, 30])
print(punct1) ==> Punct(x=10, y=20, z=30)

# _replace()
punct2 = punct1._replace(y=99)
print(punct2) ==> Punct(x=10, y=99, z=30)

# _asdict()
print(punct2._asdict()) ==> {'x': 10, 'y': 99, 'z': 30}

Crearea de instanțe nametuple din obiecte iterabile - Creating nametuple instances from iterables

Metoda ._make() acceptă orice obiect iterabil (ex. o listă, un tuplu sau un generator) cu condiția ca numărul de elemente să corespundă numărului de câmpuri definite în tuplul.

The ._make() method accepts any iterable (ex. list, tuple, or generator) as long as the number of items matches the number of fields defined in the named tuple.

from collections import namedtuple

# Definirea clasei namedtuple
Persoană = namedtuple("Persoană", ["nume", "vârstă", "oraș"])

# Crearea unui obiect iterabil
date_persoană = ["Andrei", 45, "Craiova"]

# Crearea instanței namedtuple din obiectul iterabil
instanță_persoană = Persoană._make(date_persoană)

print(instanță_persoană) ==> Persoană(nume='Andrei', vârstă=45, oraș='Craiova')
  • Ordinea contează: elementele din obiectul iterabil trebuie să respecte exact ordinea câmpurilor specificată la definirea namedtuple.
  • Validarea lungimii: dacă obiectul iterabil conține mai puține sau mai multe elemente decât numărul de câmpuri așteptat, Python va genera o eroare de tip TypeError.
  • Order matters: The elements in your iterable must match the exact field order specified when defining the namedtuple.
  • Length validation: If the iterable has fewer or more items than the expected number of fields, Python will raise a TypeError.
from collections import namedtuple

# Definirea clasei namedtuple
Persoană = namedtuple("Persoană", ["nume", "vârstă", "oraș"])
date_persoană = ["Andrei", 45, "Craiova"]

try:
    # asigură că putem verifica lungimea în siguranță
    tuplu_date = tuple(date_persoană)
    
    # Verifică lungimea obiectului iterabil şi numărului de câmpuri din namedtuple
    if len(tuplu_date) != len(Persoană._fields):
        raise ValueError(f"Așteptat {len(Persoană._fields)} elemente rezultate {len(tuplu_date)}")

except ValueError as e:
    print(f"Eroare la crearea instanței: {e}")

else:
    # Acest bloc se execută doar dacă nu este o eroare în blocul try
    instanță_persoană = Persoană._make(tuplu_date)
    print("Instanță creată:", instanță_persoană)
==> Instanță creată: Persoană(nume='Andrei', vârstă=45, oraș='Craiova')

Argumente opționale cu namedtuple() - Optional Arguments With namedtuple()

Funcția collections.namedtuple() acceptă trei argumente de tip keyword: defaults, rename și module.

The collections.namedtuple() function accepts three keyword arguments: defaults, rename, and module.

Rezumatul argumentelor opționale
Argument Tip Implicit Scop
defaults iterabil sau None None Furnizează valori implicite pentru câmpuri.
rename bool False Corectează automat numele de câmpuri invalide
module str None Suprascrie atributul __module__ al clasei

defaults asociază valori implicite, de la dreapta la stânga. Dacă ai trei câmpuri și furnizezi două valori implicite, ultimele două câmpuri devin opționale, în timp ce primul rămâne obligatoriu.

defaults assigns default values ​​from right to left. If you have three fields and provide two default values, the last two fields become optional, while the first remains mandatory.

from collections import namedtuple

# x este obligatoriu, y implicit este 0, iar z implicit este 10
Punct = namedtuple("Punct", ["x", "y", "z"], defaults=(0, 10))

punct1 = Punct(5) 
print(punct1)           ==> Punct(x=5, y=0, z=10)
punct2 = Punct(5, 2)    
print(punct2)           ==> Punct(x=5, y=2, z=10)
punct3 = Punct(5, 2, 3)
print(punct3)           ==> Punct(x=5, y=2, z=3)

Tupluri cu câmpuri denumite și indicii de tip - Tuples With Named Fields and Type Hints

În Python, tuplurile cu câmpuri denumite și indicii de tip (type hints) sunt implementate folosind typing.NamedTuple. Această clasă îmbină eficiența memoriei și imuabilitatea unui tuplu standard cu lizibilitatea unei clase, permițând accesarea câmpurilor după nume, în loc de indici numerici.

In Python, tuples with named fields and type hints are implemented using typing.NamedTuple. This class combines the memory efficiency and immutability of a standard tuple with the readability of a class, allowing you to access fields by name rather than numeric indexes.

from typing import NamedTuple

    username: str

Adăugarea valorilor implicite (default) pentru câmpuri si ordinea lor - Adding default values ​​for fields and their order.

În Python, regula obligatorie este că câmpurile cu valori implicite trebuie să fie puse întotdeauna la sfârșitul clasei, după cele fără valori implicite. Acest lucru este similar cu parametrii poziționali și cei de tip cuvânt-cheie. Legătura dintre ele constă în modul în care gestionăm informațiile obligatorii față de cele suplimentare.

In Python, the mandatory rule is that fields with default values ​​must always be placed at the end of the class, after those without default values. This is similar to positional and keyword parameters. The connection between them lies in how we handle mandatory information vs supplementary information.

from dataclasses import dataclass

    # Câmpuri opționale (cu valori implicite)
    preţ: float = 0.0
    greutate: int = 100
    email: str = "fică@tâmplar.com"

Regula de aur – elementele obligatorii apar primele, iar cele opționale, la urmă. Nu poți plasa un parametru pozițional (obligatoriu) după unul cu valoare implicită (opțional) – Pizza: Blatul și sosul sunt obligatorii (elemente de bază) – nu poți avea o pizza fără ele. Ingredientele suplimentare (ciuperci, măsline) sunt opționale – le adaugi doar dacă dorești și în orice ordine alegi.

The Golden Rule – mandatory elements come first, and optional ones come last. You cannot place a positional (mandatory) parameter after one with a default value (optional) — Piza: The crust and sauce are essential (basic elements)—you can't have a pizza without them. Additional toppings (mushrooms, olives) are optional - you add them only if you wish, and in any order you choose.
