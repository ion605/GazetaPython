De ce memoryview() se regăsește în secțiunile Funcții încorporate și Tipuri încorporate

Why memoryview() in Built-in Functions and Built-in Types

Deși este listat în pagina de documentație dedicată funcțiilor încorporate (Built-in Functions) sub forma memoryview(object), memoryview este, în esență, o clasă și un tip încorporat (Built-in Type), inclus în categoria tipurilor de secvențe binare (Binary Sequence Types).

While it is listed under the Built-in Functions documentation page as memoryview(object), memoryview itself is fundamentally a class and a Built-in Type grouped under Binary Sequence Types.

Funcționează ca o funcție de tip "fabrică" (constructor)
La fel ca multe elemente din lista de "funcții încorporate" (built-in functions) a limbajului Python (precum int(), list(), str() și dict()), memoryview este, din punct de vedere tehnic, un constructor de clasă. Python include acești constructori în categoria funcțiilor încorporate, deoarece interfața lor principală, în activitatea de programare curentă, este o funcție globală care poate fi apelată direct pentru a instanția un obiect.
It acts as a factory function (Constructor)
Like many items on Python's "Built-in Functions" list (such as int(), list(), str(), and dict()), memoryview is technically a class constructor. Python lists these constructors under Built-in Functions because their primary interface in day-to-day coding is a global, directly callable function used to instantiate an object.
Un obiect memoryview nu poate exista de sine stătător
Spre deosebire de tipurile fundamentale, precum int sau list, care pot fi instanțiate ca obiecte goale (de exemplu, x = list()), memoryview() necesită un obiect existent de care să se atașeze.
Apelarea memoryview() fără argumente generează o eroare de tip TypeError.
Acesta funcționează strict ca un instrument utilitar (sau o funcție de tip "wrapper") menit să expună, în mod sigur, protocolul de buffer de nivel C din Python.
Deoarece comportamentul său este cel al unei funcții de procesare — primește un obiect și returnează o "vizualizare" a acestuia, fără a crea o copie a datelor — se integrează perfect în modelul conceptual al unei funcții predefinite (built-in).
A memoryview cannot exist on its own
Unlike pure types like int or list, which can be instantiated empty (e.g., x = list()), memoryview() requires an existing object to bind to.
Calling memoryview() without an argument throws a TypeError.
It functions strictly as a utility tool (or a wrapping function) to safely expose Python's C-level buffer protocol.
Because its behavior behaves purely like a processing function—taking an object in, and returning a zero-copy "view" of it—it fits perfectly into the conceptual mental model of a built-in function.

Înțelegerea memoryview - Understand memoryview

Imaginează-ți o carte masivă și grea. Dacă un prieten îți cere să vadă paginile de la 50 la 100, o secvență tradițională din Python (cum ar fi un șir de octeți) va fotocopia acele 50 de pagini și i le va înmâna. Dacă faci acest lucru de mii de ori, risipești o cantitate uriașă de hârtie, timp și energie.

Un obiect de tip "memoryview" este ca un indicator. În loc să copieze ceva, acesta indică pur și simplu direct către paginile 50–100 din cartea originală. Poți vedea datele, le poți citi și — dacă acea carte este un caiet care permite ștergerea și rescrierea (un "bytearray") — poți chiar să rescrii textul.

Imagine a massive, heavy book. If a friend asks to see pages 50 through 100, a traditional Python sequence (such as a byte string) will photocopy those 50 pages and hand them over. If you do this thousands of times, you end up wasting a huge amount of paper, time, and energy.

A "memoryview" object acts like a pointer. Instead of copying anything, it simply points directly to pages 50–100 in the original book. You can view the data, read it, and—if the book happens to be a notebook that allows for erasing and rewriting (a "bytearray")—you can even rewrite the text.

Este un înveliș, nu un container
Un obiect memoryview nu stochează, în sine, nicio dată. Dacă ștergi obiectul original sau dacă acesta iese din domeniul de vizibilitate (scope), vizualizarea își pierde sursa de date. Este, practic, o fereastră către o zonă de memorie care aparține altcuiva.
Necesită "protocolul de buffer" (Buffer Protocol)
Suportate: bytes, bytearray, array.array
Ne-suportate: list, str, dict, int
Partajează memoria
Dacă efectuezi o modificare printr-un memoryview mutabil, obiectul original se modifică instantaneu. Nu se mută și nu se duplică nicio dată.
It is a Wrapper, Not a Container
A memoryview doesn't actually store any data itself. If you delete the original object or it goes out of scope, the view loses its data source. It is purely a window looking at someone else's memory.
It Requires the "Buffer Protocol"
Supported: bytes, bytearray, array.array
Not Supported: list, str, dict, int
It Shares Memory
If you make a change through a mutable memoryview, the original object changes instantly. No data is moved or duplicated.
# Metodă rapidă (memoryview indică spre date)
date_masive = b"A" * 1000000

# Încadrează într-o fereastră de vizualizare
vizualizare_memorie = memoryview(date_masive)

# Aceasta creează o fereastră-pointer de dimensiuni minuscule. 
# Memoria totală utilizată rămâne la ~1,0 Megaocteți. Nu a fost copiat niciun octet!
felie_eficienta = vizualizare_memorie[500000:]
print(felie_eficienta) ==><memory at 0x00000225DD7F2080>

Conversia tipurilor de date - Casting Data Types

Deoarece memoryview examinează octeții din memoria brută, poate realiza o operațiune incredibilă numită "conversie" (casting). Aceasta permite modificarea modului în care sunt interpretate datele binare, în timp real, fără a schimba structura memoriei subiacente.

Because memoryview looks at raw memory bytes, it can do something incredible called casting. It can change how it interprets the binary data on the fly without changing the underlying memory structure.

import array

# Create an array of signed integers (occupying 2 or 4 bytes each in memory)
numere = array.array('i', [1, 2, 3, 4])
print(numere) ==> array('i', [1, 2, 3, 4])

# Vizualizarea octeților bruti ai acelor numere întregi
vizualizare_octeti = memoryview(numere).cast('B')
print(vizualizare_octeti) ==> <memory at 0x000001DD5610CC40>

# Câți octeți ocupă, de fapt, în memorie!
print(len(numere))             ==> 4
print(len(vizualizare_octeti)) ==> 16

import array

# Crearea unui tablou de numere întregi cu semn ('i' ocupă, de obicei, 4 octeți per element)
date_originale = array.array('i', [1, 2])

# Crearea unei vizualizări a memoriei (memoryview) pentru acest tablou
vizualizare_memorie = memoryview(date_originale)

# Conversia vizualizării către octeți fără semn ('B')
# Fiecare număr întreg de 4 octeți va fi reinterpretat ca patru segmente de câte 1 octet
vizualizar_octeti = vizualizare_memorie.cast('B')

print("Lista originală:", date_originale.tolist()) ==> Lista originală: [1, 2]
# Afișează reprezentarea în octeți (Little-Endian)
print("Reprezentarea pe octeți:", vizualizar_octeti.tolist())
==> Reprezentarea pe octeți: [1, 0, 0, 0, 2, 0, 0, 0]

# Modificarea memoriei subiacente prin intermediul vizualizării convertite
# Modificarea primului octet al celui de-al doilea număr întreg (indexul 4)
vizualizar_octeti[4] = 99

# Modificarea se reflectă instantaneu în tabloul original, fără a fi necesară nicio copiere!
print("Lista originală modificată:", date_originale.tolist()) ==> Lista originală modificată: [1, 99]
